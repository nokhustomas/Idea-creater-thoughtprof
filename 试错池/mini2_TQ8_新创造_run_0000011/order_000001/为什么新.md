# 为什么新

## 方案一：Git diff / diff 命令
- 名称：Git diff（以及 Unix `diff` 工具）
- 出处链接：https://git-scm.com/docs/diff
- 做法：对两个文本文件做逐行（Myers 算法）比较，输出 unified diff 格式的 patch，标注哪些行被增删改；只看到字符层面的行号差异，完全不解析代码语义。
- 与本创造的差异：Git diff 看到的是行号和字符串，无法告诉你"这是函数定义被改了"还是"这是一段字符串里多了个词"；CodeDiff 直接解析 AST，告诉你"哪个函数 / 类被新增、删除或修改"。

## 方案二：jscpd（JavaScript Copy/Paste Detector）
- 名称：jscpd
- 出处链接：https://github.com/kuchurenko/jscpd
- 做法：在代码库内部扫描重复片段，基于 token 序列的相似度匹配，输出哪些文件之间存在复制粘贴块，主要用于治理重复代码和代码异味。
- 与本创造的差异：jscpd 只关心"相似度"和"重复块"，不区分新旧版本，也不输出"新增 / 删除 / 修改"这种结构化变更序列；CodeDiff 专注于"两个版本之间"的结构性差异，是版本演进视角而不是重复检测视角。

## 方案三：Source Map / 代码覆盖率工具（Coverage Tools）
- 名称：Source Map 及配套的 Coverage 工具（如 Istanbul / coverage.py）
- 出处链接：https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/SourceMap
- 做法：把编译产物（JS / 字节码）的执行轨迹映射回源码，回答"运行时哪一行代码被跑过 / 没被跑到"，关注的是测试覆盖率和运行时行为，不是源码结构在不同版本之间的差异。
- 与本创造的差异：Coverage 关心的是"代码被执行了多少"，CodeDiff 关心的是"代码本身在版本演进中如何变化"；二者面向的问题域完全不同——一个是运行时观测，一个是静态结构对比。

## 本创造与上述方案的差异
直接对比两个版本代码的 AST 结构，输出人类可读的结构变更说明（哪个函数/类被新增、删除、修改，参数如何变化），而不是机器导向的 patch 文件、重复度评分或运行时覆盖率数据；目标是让代码审查者只看一行摘要就能定位关键变更，而不必逐行阅读 diff。
