# 给谁用

## 场景一：代码审查

审查者需要快速定位两个 Python 版本之间的结构变化，而不想逐行阅读补丁。

1. 准备修改前的 `old.py` 和修改后的 `new.py`。
2. 在项目目录运行 `python codediff.py old.py new.py`。
3. 查看终端报告和 `diff_report.txt`，直接确认新增、删除或修改的函数、类及参数。

## 场景二：重构验证

开发者希望确认重构只改变代码结构，没有意外改变函数接口或类成员。

1. 将重构前的版本保存为 `old.py`，将重构后的版本保存为 `new.py`。
2. 运行 `python codediff.py old.py new.py`。
3. 对照报告检查同名函数的参数变化，以及类方法的增删；再结合完整测试验证逻辑行为。

## 场景三：学习新代码

学习者想快速了解一个项目版本更新后，具体是哪些函数或类发生了变化。

1. 获取项目更新前后的两个 Python 文件。
2. 将它们放在同一目录，并分别命名为 `old.py` 和 `new.py`。
3. 运行 `python codediff.py old.py new.py`，阅读结构化报告，定位关键改动所在位置。
4. 根据报告进入对应文件阅读实现细节，无需先逐行浏览整个文本 diff。
