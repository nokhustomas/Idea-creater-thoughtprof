# 我的新创造：因果感知型代码差异分析器（Causal Code Diff, CCD）

## 一句话定位
一个能识别代码变更"真正语义影响"的静态分析工具，比传统 diff 更进一步：不仅告诉你"哪些行变了"，还告诉你"这次改动为什么会改变程序行为、影响哪些输出路径"。

## 解决的根本问题
现有代码 diff 工具（diff、git diff、codediff 等）只能做**文本/语法层面**的对比：哪些行被增删改。但开发者和代码评审者真正关心的不是"哪行字变了"，而是：
- 这次改动会不会让函数返回值不一样？
- 改动有没有改变某个 if 分支的走向？
- 影响范围波及到哪些调用方？会不会传到下游模块？

现在的做法是人工肉眼看 diff、再人脑推演，耗时且容易遗漏。本工具把"语义影响"这一步自动化。

## 核心方法
1. **抽象语法树（AST）+ 控制流图（CFG）联合建模**：用 Python 自带的 `ast` 模块把两份代码解析成 AST，再构建每个函数的 CFG。
2. **差异传播算法**：在 AST 上做结构对齐（用树编辑距离 + 节点哈希），把"改动节点"标记为种子，沿 CFG 边的正向（数据流）和反向（调用栈）做可达性分析，标记所有"可能被影响"的节点。
3. **影响分级**：根据可达路径的长度、是否跨越函数边界、是否触及 return/分支判断点，把每处影响分成三级：致命（影响返回值或核心分支）、警告（影响中间变量或边界条件）、提示（仅影响局部重命名）。
4. **零外部依赖**：只使用 Python 标准库（ast、difflib、dataclasses、json），确保离线可跑、可复现。

## 应用场景
- 代码评审（Code Review）：自动标注 PR 中"真正会改变行为"的行
- 回归测试挑选：根据影响范围自动选出最小测试集
- 教学/学习：让初学者直观看到"改一行影响多大"

## 与现有方案的差异（一句话）
- vs `diff`/`git diff`：我们做**语义**影响，不是文本行差。
- vs `codediff.py`（同目录已有）：我们建模 CFG 做传播，不是单层 AST 节点匹配。
- vs 商业工具（Sourcetrail、CodeScene）：我们是零依赖、单文件、几十行可读的 Python 脚本，不依赖大型索引数据库。
