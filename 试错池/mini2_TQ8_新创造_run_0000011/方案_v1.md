# 方案 v1

## 核心
CodeDiff 是一个本地运行的代码语义差异分析工具，它通过抽象语法树(AST)解析来对比两个代码文件的结构级差异，而非逐行文本差异。核心价值在于：让代码审查者一眼看清"函数被重构了"还是"只是改了变量名"。关键取舍是只支持 Python（利用标准库 ast 模块），不做成通用多语言工具以保持轻量。

运行：`python codediff.py old.py new.py`

## 原文
【概述】
CodeDiff 是一个 Python 脚本，通过对比两个代码文件的抽象语法树(AST)，输出结构层面的差异报告。解决现有 diff 工具只报"哪行变了"但不报"变了什么"的问题。

【运行方式】
保存为 codediff.py（文件名：codediff.py，内容：主程序脚本），直接运行：python codediff.py old_file.py new_file.py（顺序：需先准备好old_file.py和new_file.py两个文件，再运行此命令）
输出差异报告到终端并保存为 diff_report.txt（文件名：diff_report.txt，内容：结构差异报告）

【原型实现逻辑】
1. 用 Python 内置 ast 模块解析两个文件为 AST 树
2. 遍历 AST 提取函数定义、类定义、import 语句、函数调用等关键节点
3. 对比两组节点的增删改情况
4. 输出结构化报告，包含：新增了哪些函数/类、删除了哪些、哪些函数的参数或内部逻辑变了

【为什么新.md 内容】
文件: 为什么新.md（文件名：为什么新.md，内容：三个已有方案对比及本创造差异）
- 方案一：Git diff / diff 命令（https://git-scm.com/docs/diff）- 纯文本逐行对比，无法理解代码结构
- 方案二：AST-based tools（如 jscpd、clone-digger）- 主要用于检测重复代码，不做版本间差异对比
- 方案三：Sourcemap/Coverage tools - 关注运行时覆盖，非代码结构对比
本创造差异：直接对比两个版本代码的 AST 结构，输出人类可读的结构变更说明，而非机器导向的 patch 文件

【价值证明 demo.py】
文件: demo.py（文件名：demo.py，内容：价值证明脚本，需包含sample_v1.py和sample_v2.py的生成代码）
- 创建两个测试文件：sample_v1.py（原始版）和 sample_v2.py（修改版）（文件名：sample_v1.py和sample_v2.py，内容：测试用Python代码）
- 运行 python demo.py
- 脚本自动调用 CodeDiff 分析两个文件，打印结构差异摘要
- 输出示例："新增函数: process_data, 删除函数: legacy_func, 修改函数: calculate (参数从2个变为3个)"
- 证明价值：用户无需逐行阅读 diff 即可知道核心变更

【给谁用.md 内容】
文件: 给谁用.md（文件名：给谁用.md，内容：三个使用场景及步骤）
场景一：代码审查——审查者运行 codediff.py old.py new.py，快速定位关键变更
场景二：重构验证——重构前后运行对比，确认只改了结构而非逻辑
场景三：学习新代码——看项目更新日志后，用工具定位具体改动的函数位置

【验收】
验收：python codediff.py sample_v1.py sample_v2.py && test -f diff_report.txt（命令：python codediff.py sample_v1.py sample_v2.py && test -f diff_report.txt，期望：退出码 0 且生成 diff_report.txt）

验收：python demo.py（命令：python demo.py，期望：退出码 0 且打印至少一组差异数据）
