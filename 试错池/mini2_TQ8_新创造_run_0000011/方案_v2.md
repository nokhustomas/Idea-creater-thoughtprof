# 方案 v2

## 核心
CodeDiff 是一个对比两个Python文件AST结构的工具，输出函数/类的增删改信息。核心价值在于让代码审查者只看报告就知道"新增了哪个函数、删除了哪个、谁改了参数"，不用逐行读diff。关键取舍是放弃通用性，只专注Python的AST层面对比，确保输出可读而非机器导向的patch文件。

运行：`python demo.py`

## 原文
【概述】
CodeDiff 是一个 Python 脚本（文件：codediff.py），通过对比两个代码文件的抽象语法树(AST)，输出结构层面的差异报告。解决现有 diff 工具只报"哪行变了"但不报"变了什么"的问题。（Python 版本要求：3.6+，因为使用了 ast 模块的 parse_file 方法；Windows/Mac/Linux 均可运行）

【运行方式】
保存为 codediff.py，直接运行：python codediff.py old_file.py new_file.py
输出差异报告到终端并保存为 diff_report.txt（验收：python codediff.py sample_v1.py sample_v2.py && test -f diff_report.txt 期望：退出码0且生成diff_report.txt）

【原型实现逻辑】
1. 用 Python 内置 ast 模块解析两个文件为 AST 树（顺序：先安装Python 3.6+才能使用ast模块；最容易错的地方：未安装Python或版本低于3.6）
2. 遍历 AST 提取函数定义（FunctionDef）、类定义（ClassDef）、import 语句（Import/ImportFrom）等关键节点，建立节点集合
3. 对比两组节点的增删改情况：新增节点为added，删除节点为removed，名称相同但内容不同的为modified（顺序：先完成步骤2才能执行步骤3；最容易错的地方：节点比对时未区分名称相同但内容不同的情况）
4. 输出结构化报告，采用纯文本格式，每行一个变更，格式如："+ 函数名: process_data"（新增）、"- 函数名: legacy_func"（删除）、"~ 函数名: calculate (参数从2个变为3个)"（修改）
5. 包含基础容错：文件不存在时报错并退出（验收：python codediff.py notexist.py new.py 期望：非0退出码并报错"File not found"），语法错误文件跳过该文件并警告（验收：python codediff.py syntax_error.py new.py 期望：警告信息但继续执行）

【为什么新.md 内容】
文件: 为什么新.md（验收：ls -la 为什么新.md 期望：文件存在）
- 方案一：Git diff / diff 命令（https://git-scm.com/docs/diff）- 纯文本逐行对比，无法理解代码结构
- 方案二：jscpd（https://github.com/kucherenko/jscpd）- 主要用于检测重复代码，不做版本间差异对比
- 方案三：Sourcemap/Coverage tools（https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/SourceMap）- 关注运行时覆盖，非代码结构对比
本创造差异：直接对比两个版本代码的 AST 结构，输出人类可读的结构变更说明，而非机器导向的 patch 文件

【价值证明 demo.py】
文件: demo.py（验收：ls -la demo.py 期望：文件存在）
- 脚本内含创建测试文件的函数，自动生成 sample_v1.py（原始版含函数 process_data、calculate）和 sample_v2.py（修改版含函数 process_data、calculate 参数增加、新增 helper）
- 运行 python demo.py（验收：python demo.py 期望：退出码0）
- 脚本自动调用 CodeDiff 分析两个文件，打印结构差异摘要
- 输出示例："新增: helper, 修改: calculate (参数从2个变为3个)"
- 证明价值：用户无需逐行阅读 diff 即可知道核心变更

【给谁用.md 内容】
文件: 给谁用.md（验收：ls -la 给谁用.md 期望：文件存在）
场景一：代码审查——审查者运行 python codediff.py old.py new.py，快速定位关键变更
场景二：重构验证——重构前后运行对比，确认只改了结构而非逻辑
场景三：学习新代码——看项目更新日志后，用工具定位具体改动的函数位置

【验收】
验收：python codediff.py sample_v1.py sample_v2.py && test -f diff_report.txt（期望：退出码0且diff_report.txt存在）
验收：python demo.py && test -f diff_report.txt（期望：退出码0且demo执行后生成diff_report.txt）
验收：ls -la 为什么新.md 给谁用.md demo.py codediff.py | wc -l（期望：输出4，证明4个文件都存在）
