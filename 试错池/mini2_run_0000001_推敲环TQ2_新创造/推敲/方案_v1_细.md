# 方案 v1 细件

## idea_validator.py
- 文件：idea_validator.py：主程序，入口函数main()，使用argparse解析--idea参数，调用search_module.search()和analyze_module.analyze()，输出JSON报告
- 文件：why_new_demo.py：价值证明脚本，模拟三个已有方案并输出对比数据
- 数据：入 命令行参数：--idea "创意描述文本"；出 JSON格式报告，包含feasible(boolean)、reason(string)、score(float)字段；样例 输入：python3 idea_validator.py --idea "语音控制的markdown编辑器"
输出：{"feasible": true, "reason": "该领域已有语音输入API，但集成到markdown编辑器的方案较少", "score": 0.75}
- 数字：3（为什么新.md要求对比三个已有方案，本脚本分析时也检查三个方案）
- 步骤 1：用argparse解析--idea参数获取创意描述
- 步骤 2：调用search_module在本地数据库模拟搜索相似方案
- 步骤 3：调用analyze_module分析创意的可行性和新颖性
- 步骤 4：将分析结果以JSON格式输出到stdout
- 步骤 5：why_new_demo.py模拟三个已有方案的运行并输出对比分数
- 注意：JSON输出必须符合标准格式，否则下游解析会失败
- 注意：创意描述过短时分析结果可能不准确
- 注意：本地模拟搜索只能返回预设数据，无法真正联网搜索
- 验收：python3 idea_validator.py --idea "语音控制的markdown编辑器" && echo $?

需方案岗拍的决策点：
- 搜索模块是使用本地模拟数据还是真实文件系统中的已有方案文本
- 分析模块的新颖性判断阈值是基于关键词匹配还是语义相似度
- 是否需要额外文件存放预设的三个已有方案数据供why_new_demo.py调用
