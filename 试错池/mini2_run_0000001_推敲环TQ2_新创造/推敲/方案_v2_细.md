# 方案 v2 细件

## idea_conflict.py
- 文件：idea_conflict.py：主程序入口，argparse解析--idea参数，调用detect_conflict函数，输出JSON格式结果
- 数据：入 命令行参数--idea后跟创意关键词字符串；出 JSON字符串，包含idea、conflict_score、similar_items字段；样例 输入: python3 idea_conflict.py --idea "语音控制的markdown编辑器"
输出: {"idea": "语音控制的markdown编辑器", "conflict_score": 0.75, "similar_items": [{"title": "语音Markdown编辑器", "similarity": 0.85}, ...]}
- 数字：0.5（方案中未明确，假设取0.5作为冲突阈值，高于此值认为存在冲突）
- 数字：3（方案中未明确，假设取top3作为similar_items返回数量）
- 步骤 1：安装jieba和sklearn依赖（pip install jieba scikit-learn）
- 步骤 2：用argparse解析--idea命令行参数
- 步骤 3：读取同目录mini_corpus.txt作为本地知识库
- 步骤 4：用jieba分词对输入创意进行中文分词
- 步骤 5：用TfidfVectorizer对分词结果和语料库进行向量化
- 步骤 6：用cosine_similarity计算创意与语料库每条的相似度
- 步骤 7：取相似度最高的前N条（N由numbers中假设的3决定），计算平均冲突度
- 步骤 8：输出JSON格式结果，conflict_score为0-1之间小数
- 注意：编码问题：mini_corpus.txt必须是utf-8编码，否则读取会报编码错误
- 注意：空输入：如果--idea参数为空，jieba分词会返回空列表导致后续向量化失败
- 注意：语料库为空：如果mini_corpus.txt为空文件，向量化会报错
- 验收：python3 idea_conflict.py --idea "语音控制的markdown编辑器" | grep -q "conflict_score" && echo "PASS" || echo "FAIL"

## mini_corpus.txt
- 文件：mini_corpus.txt：纯文本文件，每行一条技术方案摘要，共需1000行
- 数据：入 无（静态文件）；出 每行一条技术方案的中文或英文描述；样例 第1行: 基于语音识别的笔记应用
第2行: VSCode语音输入插件
第3行: Markdown实时预览编辑器
- 数字：1000（方案中明确：1000条常见技术方案摘要）
- 数字：500（check中明确：wc -l输出大于500）
- 步骤 1：创建一个空文件mini_corpus.txt
- 步骤 2：每行写入一条简短的技术方案描述（中文优先，也可以包含英文）
- 步骤 3：共写入至少500行，建议写入1000行以符合方案要求
- 步骤 4：确保文件编码为UTF-8
- 注意：行数不足：少于500行会导致check失败
- 注意：编码错误：如果不是UTF-8，Python读取可能报错
- 注意：空行：文件中不应有空行，否则会被wc计入导致实际内容行数不足
- 验收：wc -l mini_corpus.txt | awk '{if($1>500) print "PASS"; else print "FAIL"}'

- 做法: 展示近期GitHub上最热门的开源项目

### 2. Alfred Workflows
- 链接: https://www.alfredapp.com/workflows/
- 做法: 提供macOS上的生产力自动化工作流
- 差异: 本创意专注于创意冲突检测而非通用自动化

### 3. VSCode语音插件
- 链接: https://marketplace.visualstudio.com/items?itemName=ms-vscode.voicemacro
- 做法: 在VSCode中通过语音触发命令
- 差异: 本创意是通用冲突检测工具非特定编辑器插件
- 数字：3（方案中明确：三个最接近方案）
- 数字：3（check中明确：grep -c http输出大于等于3）
- 步骤 1：创建why_new.md文件
- 步骤 2：写入三个已有方案的详细信息，每个包含名称、出处链接、本方案做法描述
- 步骤 3：每个方案后写一行本创意与它的差异点
- 步骤 4：确保文件中包含至少3个http链接
- 注意：链接缺失：每个方案必须有可点击的http链接，否则check失败
- 注意：方案不足：必须正好三个方案，少于或多于都会导致不符合要求
- 注意：差异点缺失：每个方案必须有明确的差异点描述
- 验收：grep -c "http" why_new.md | awk '{if($1>=3) print "PASS"; else print "FAIL"}'

## value_demo.py
- 文件：value_demo.py：价值对比实验脚本，对比本工具与随机词检测的输出差异
- 数据：入 无（运行时读取mini_corpus.txt和idea_conflict.py）；出 打印conflict_score数值，展示本工具相对于随机基线的优势；样例 python3 value_demo.py
本工具冲突度: 0.75
随机基线冲突度: 0.23
结论: 本工具检测到更高的冲突度，证明能有效识别已有方案
- 数字：0.75（示例输出中的假设值，实际运行由代码逻辑决定）
- 数字：0.23（示例输出中的假设值，随机生成字符串的预期相似度较低）
- 步骤 1：导入subprocess和random模块
- 步骤 2：定义一个测试创意（如"语音控制的markdown编辑器"）
- 步骤 3：调用idea_conflict.py获取该创意的conflict_score
- 步骤 4：生成一个随机字符串（如8位随机字母），同样调用idea_conflict.py获取conflict_score
- 步骤 5：打印两个分数并输出对比结论
- 注意：路径问题：需确保mini_corpus.txt和idea_conflict.py在同目录或使用绝对路径
- 注意：随机字符串过短：随机字符串如果太短可能无法正确分词导致结果异常
- 注意：依赖未安装：确保jieba和sklearn已安装
- 验收：python3 value_demo.py && echo "PASS"

## who_use.md
- 文件：who_use.md：三个具体使用场景，每个场景按步骤说明用法
- 数据：入 无（静态文件）；出 Markdown格式文本，包含三个使用场景及各自的操作步骤；样例 ## 使用场景一：独立开发者找细分方向

步骤1: 运行 python3 idea_conflict.py --idea "你的创意"
步骤2: 查看conflict_score，低于0.3表示竞争较少
步骤3: 根据similar_items调整创意差异化点

## 使用场景二：产品经理快速验证创意

步骤1: 准备多个创意关键词
步骤2: 依次运行检测脚本获取分数
步骤3: 选择分数最高的创意进行深入调研

## 使用场景三：技术博主找内容选题

步骤1: 列出自己擅长的技术领域
步骤2: 对每个领域词运行冲突检测
步骤3: 选择冲突度低的领域作为新教程主题
- 数字：3（方案中明确：三个具体使用场景）
- 数字：3（check中明确：grep -c "步骤"输出大于等于3）
- 步骤 1：创建who_use.md文件
- 步骤 2：写入三个使用场景，每个场景包含场景描述和具体步骤
- 步骤 3：每个场景的步骤用"步骤1:"、"步骤2:"等形式编号
- 步骤 4：确保全文包含至少3个"步骤"关键词
- 注意：步骤数不足：每个场景至少需要一步，总共至少3步才能满足check
- 注意：场景重复：三个场景必须不同，不能是同一场景的不同表述
- 注意：步骤描述模糊：必须是可以直接照做的具体操作，不能是抽象描述
- 验收：grep -c "步骤" who_use.md | awk '{if($1>=3) print "PASS"; else print "FAIL"}'

需方案岗拍的决策点：
- 冲突度阈值0.5的设定依据是什么，超过多少算高冲突需要放弃创意
- similar_items返回top3的数量设定依据是什么，是否需要可配置
- value_demo.py中随机基线的生成方式（字符集、长度）如何确定
- 如果用户输入包含繁体字或特殊字符，jieba分词是否需要额外处理
