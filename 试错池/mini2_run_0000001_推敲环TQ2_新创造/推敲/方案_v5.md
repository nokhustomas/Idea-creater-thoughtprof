# 方案 v5

本地创意可行性分析器V2：输入创意描述，检索本地技术语料库计算三维可行性评分，输出JSON报告

运行：`python3 feasibility_analyzer.py --idea "语音控制的markdown编辑器"`

1. **feasibility_analyzer.py** — 主程序：接收创意描述，用jieba分词+本地语料检索+clarity/feasibility/uniqueness三维评分，输出JSON报告，处理语料库文件不存在或为空时返回默认评分；文件 feasibility_analyzer.py, tech_corpus.json, why_new.md, value_demo.py, who_use.md；验收：python3 feasibility_analyzer.py --idea "语音控制的markdown编辑器" 退出码为0且输出包含feasibility_score
2. **tech_corpus.json** — 本地知识库：200条GitHub热门开源项目摘要（含name/description/tags），过滤空description后保留>=150条；文件 tech_corpus.json；验收：python3 -c "import json;d=json.load(open('tech_corpus.json'));print(len([x for x in d if x.get('description')]))" 输出>=150
3. **why_new.md** — 说明三个最接近方案：GitHub语音项目(https://github.com/topics/voice-control)、VSCode语音插件、语音markdown工具，本工具差异点是'多维度评分+本地离线可用'；文件 why_new.md；验收：grep -c http why_new.md 输出>=3
4. **value_demo.py** — 价值证明实验：分别分析'语音markdown'和随机描述，对比feasibility_score差异，证明工具能识别有价值创意；文件 value_demo.py；验收：python3 value_demo.py 退出码为0且打印feasibility_score
5. **who_use.md** — 三个使用场景：独立开发者找方向、产品经理验证创意、技术博主选题，每场景含背景描述+至少3个步骤(步骤一/Step1等形式)；文件 who_use.md；验收：python3 -c "import re;print(len(re.findall(r'(步骤一|步骤\d|Step\d|步骤\s)',open('who_use.md').read())))" 输出>=9

待核实假设：
- tech_corpus.json通过curl https://api.github.com/search/repositories?q=stars:>1000&per_page=200获取，假设GitHub API正常返回数据
- jieba分词对'语音控制'、'markdown'能正确识别，假设无需额外用户词典
- 三个对比方案（GitHub语音项目、VSCode语音插件、语音markdown工具）的链接真实有效
- 当前系统已安装python3标准库（含json/subprocess/re等）
- 用户会提供有意义的创意描述，非空字符串

本版改动：
- 修改feasibility_analyzer.py：1）增加输入验证，当--idea为空或仅空白字符时返回错误提示并退出码1；2）特殊字符用shlex.quote转义防止注入；3）uniqueness公式改为uniqueness=1-(匹配数/max(1,语料库实际条目数))避免除零；4）输出JSON增加differences字段列出与相似项目的差异点；5）tech_corpus.json不存在或为空时默认评分设为0.4（偏低以提醒用户补充语料）
- 修改tech_corpus.json获取方式：用Python urllib代替curl（标准库要求），parse脚本纯Python实现
- 修改value_demo.py：1）在调用subprocess前检查feasibility_analyzer.py是否存在；2）增加示例数量至5个（2个有意义+3个随机）并打印平均值以证明统计显著性
