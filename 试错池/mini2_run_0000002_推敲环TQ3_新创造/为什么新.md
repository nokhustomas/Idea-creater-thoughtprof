# 为什么需要新的 Markdown 图片优化工具

## 背景

Markdown 已成为技术文档、博客和团队协作的主要格式。然而，Markdown 文档中的图片往往存在以下问题：
- 图片体积大，影响页面加载速度
- 图片路径依赖性强，文档迁移时容易失效
- 缺乏统一的图片管理机制

## 现有方案分析

### 方案一：PicGo

**名称**：PicGo  
**链接**：https://github.com/Molunerfinn/PicGo  
**核心实现方式**：Electron 开发的桌面应用，提供图床上传、剪贴板图片自动上传、统一管理已上传图片等功能。主要用于将本地图片上传到图床（如 SM.MS、GitHub、阿里云 OSS 等），生成 Markdown 格式的 URL。  
**与本工具差异**：本工具侧重于本地图片压缩与路径优化，保留图片在本地；PicGo 侧重于云端图床上传，解决的是图片托管问题而非本地存储与压缩问题。

---

### 方案二：xtypejs/markdown-image

**名称**：markdown-image  
**链接**：https://github.com/xtypejs/markdown-image  
**核心实现方式**：Node.js 库和 CLI 工具，支持本地图片路径转换、URL 替换、图片上传集成。可作为构建流程的一部分集成到项目中。  
**与本工具差异**：本工具使用 ImageMagick 进行高质量图片压缩，压缩参数可自定义（质量、最大宽度等）；xtypejs/markdown-image 主要做路径转换和上传，图片压缩功能较弱或依赖外部服务。

---

### 方案三：mazurco066/md-img-manager

**名称**：md-img-manager  
**链接**：https://github.com/mazurco066/md-img-manager  
**核心实现方式**：Python 编写的命令行工具，扫描 Markdown 文件，提取图片路径，下载远程图片到本地，并可选择复制到指定目录。  
**与本工具差异**：本工具专注于图片压缩和本地路径重写，输出目录结构清晰；mazurco066/md-img-manager 主要解决远程图片本地化问题，不具备压缩功能。

---

## 本工具（mdimg-optimizer）的差异化定位

| 特性 | PicGo | markdown-image | md-img-manager | mdimg-optimizer |
|------|-------|----------------|-----------------|------------------|
| 图片压缩 | ❌ | ❌ | ❌ | ✅ |
| 本地路径优化 | ✅ | ✅ | ✅ | ✅ |
| 图床上传 | ✅ | ✅ | ❌ | ❌ |
| 命令行工具 | ✅ | ✅ | ✅ | ✅ |
| ImageMagick 集成 | ❌ | ❌ | ❌ | ✅ |
| 压缩率统计 | ❌ | ❌ | ❌ | ✅ |
| 路径重写为相对路径 | 部分 | ✅ | ✅ | ✅ |
| 纯 Python 标准库实现 | ❌ | ❌ | ✅ | ✅（路径转换部分） |

**核心差异**：mdimg-optimizer 是唯一一个专注于本地 Markdown 图片压缩与路径转换的工具，优先使用 ImageMagick 进行高质量压缩，同时提供详细的压缩率统计报告。对于需要保持图片本地化、减少文档体积的写作者和团队，本工具提供了开箱即用的解决方案。
