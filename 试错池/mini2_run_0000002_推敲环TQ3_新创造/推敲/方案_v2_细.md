# 方案 v2 细件

## mdimg_optimizer.py
- 文件：mdimg_optimizer.py: 主程序，包含以下函数和命令行接口
- 文件：parse_args() - 解析命令行参数，支持--input/--output/--mode/--quality/--verbose
- 文件：find_images_in_md(md_content) - 正则匹配Markdown中的图片语法(![alt](url))
- 文件：compress_image_bytes(image_path, quality) - 使用zlib.compress压缩图片字节流（对PNG有效）
- 文件：convert_path(old_path, mode, base_dir) - 路径转换：relative<->absolute
- 文件：process_markdown(input_file, output_file, mode, quality, verbose) - 主处理流程
- 文件：main() - 入口，调用上述函数
- 数据：入 Markdown文件(.md)，包含本地图片路径如![Screenshot](images/screen.png)或base64编码图片；出 处理后的Markdown文件，图片被压缩或路径被转换；样例 输入: ![img](pic/logo.png)\n输出: ![img](compressed_logo.png) （压缩后）
- 数字：9（zlib压缩级别9（最高压缩比））
- 数字：80（默认质量参数80%）
- 数字：1048576（1MB阈值）
- 步骤 1：1. 运行 python mdimg_optimizer.py --input input.md --output output.md
- 步骤 2：2. 脚本读取input.md内容
- 步骤 3：3. 用正则表达式找出所有图片引用(![alt](url))
- 步骤 4：4. 对每个图片路径：如果文件存在且大于1MB，用zlib压缩后保存到compressed目录
- 步骤 5：5. 将原Markdown中的图片路径替换为新路径或base64
- 步骤 6：6. 写入output.md
- 注意：纯Python标准库无法真正压缩PNG/JPEG像素数据，zlib只对字节流有效，实际压缩率很低
- 注意：如果图片路径是相对路径，必须确保--input文件所在目录正确，否则找不到图片
- 注意：base64编码的图片会极大增加Markdown文件体积，不建议转换
- 验收：python mdimg_optimizer.py --help 退出码0并打印帮助信息，包含--input/--output/--mode等参数说明

## demo.py
- 文件：demo.py（自动生成测试素材并运行mdimg_optimizer.py，输出压缩率等数字）
- 数据：入 无需外部输入，脚本内生成测试markdown文件和PNG图片；出 打印压缩率、转换成功率、文件大小对比等数字；样例 压缩前总大小: 102400 bytes
压缩后总大小: 35840 bytes
压缩率: 65.0%
转换成功率: 100%
处理文件数: 1
- 数字：100（PNG图片宽度（测试用固定值））
- 数字：100（PNG图片高度（测试用固定值））
- 数字：RGBA（PNG颜色模式（Python PIL兼容模式））
- 数字：65.0（期望压缩率（zlib压缩PNG通常可达60-70%压缩率））
- 数字：100（期望转换成功率（测试素材无误应100%成功））
- 步骤 1：1. 用Python标准库zlib和struct生成测试用PNG图片，保存为test_img.png
- 步骤 2：2. 生成包含相对路径图片引用的test.md，内容为![img](test_img.png)
- 步骤 3：3. 调用subprocess运行python mdimg_optimizer.py处理test.md
- 步骤 4：4. 读取生成的optimized.md和压缩后的图片文件
- 步骤 5：5. 计算原始图片与压缩后图片的字节数差，求压缩率
- 步骤 6：6. 打印压缩率、转换成功率、文件大小对比等数字
- 注意：PNG生成格式不标准导致mdimg_optimizer.py无法识别，错误表现为转换成功率为0
- 注意：路径相对路径与绝对路径混用导致图片找不到，错误表现为优化后图片仍为原大小
- 验收：python demo.py 退出码0且输出包含"压缩率:"和"成功率:"

需方案岗拍的决策点：
- 纯Python标准库(zlib)只能压缩字节流，无法真正压缩PNG/JPEG等图片的像素数据，压缩率极低。是否改用本机已装的图片处理工具（如系统自带的convert/magick）？
- 如果坚持纯标准库方案，mdimg_optimizer.py实际只能做路径转换和base64编码，压缩功能名存实亡，是否接受？
- 三个已有方案需要真实搜索，搜索关键词用什么？（如：markdown image optimizer, markdown 图片压缩工具）
- demo.py中期望压缩率65%是否合理需根据实际zlib压缩PNG的效果调整
- 是否需要在给谁用.md中说明Python版本要求（建议3.6+）
