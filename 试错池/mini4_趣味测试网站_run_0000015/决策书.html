技术栈选单页HTML还是Python服务器？

直接决定项目架构、部署方式和功能上限，info_000036-037提供了明确的技术栈参考

单页HTML方案（mind_first_principles）

为什么产出它：项目要求≤200KB，无外链，单页面最易满足(info_000005/008)

优点
  • 无需服务器，部署极简
  • 文件大小易控制，≤200KB可达成
  • 手机即开即用，契合info_000002场景
缺点
  • 无后端存储，无法保存用户数据
  • 功能扩展受限
  • 无法实现复杂逻辑

因果链：轻量需求(info_000005)→单页HTML满足≤200KB(info_000008)→手机端即开即用(info_000002)→选单页方案

关键信息：
  • 交付物要求：index.html样式脚本全内嵌，不引CDN(info_000005)
  • HTML+CSS+JS合计≤200KB(info_000008)

Python服务器方案（mind_first_principles）

为什么产出它：info_000036-037明确推荐Python+Flask/Django作为后端技术栈

优点
  • 成熟稳定，Django/Flask文档完善(info_000041)
  • 可存储用户答题数据，实现统计功能
  • 支持后续功能扩展
缺点
  • 需服务器部署，增加运维成本(info_000036托管费800-1500元/月)
  • 需Python环境，不如HTML便携

因果链：需存储用户数据→Python+Flask后端(info_000041)→服务器托管(info_000036)→选服务器方案

关键信息：
  • 技术栈推荐：Python+Flask/Django(info_000041)
  • 服务器托管费用：800-1500元/月(info_000036)
怎么选：如果追求轻量、快速上线、手机端即开即用，选单页HTML；如果需要存储用户数据、后续扩展功能、预算充足，选Python服务器

内容审查机制选人工+自建词库还是第三方API？

验收条件明确禁用词清单(info_000008)，审查机制直接决定内容合规性和上线风险

人工审核+自建词库（mind_premortem/mind_six_hats）

为什么产出它：内容审查标准已明确，需落地执行机制(info_000030-031)

优点
  • 成本可控，词库可定制
  • 灵活调整，漏判可及时补充
  • 无需第三方付费
缺点
  • 效率低，人工成本高
  • 依赖审核人员判断标准一致性
  • 漏判风险，实时性差

因果链：禁用词清单明确(info_000008)→自建词库+人工审核→成本可控但效率低→选人工方案

关键信息：
  • 禁用词：胖/丑/病/死/穷/笨/蠢/分手/离婚/成绩/工资(info_000008)
  • 内容无害化措施参考(info_000046)

第三方内容审查API（mind_premortem）

为什么产出它：line_000030提到可引入第三方内容审查服务

优点
  • 自动高效，实时过滤
  • 覆盖面广，词库定期更新
  • 减少人工审核工作量
缺点
  • 付费服务，增加成本
  • 敏感度阈值不可控，可能误杀
  • 需对接API，增加开发复杂度

因果链：需要自动化审查→第三方API服务→效率高但付费→选第三方方案

关键信息：
  • 内容审查服务可考虑第三方(info_000030)
  • 云平台通常提供内容安全API
怎么选：如果预算有限、词库规模小、重视灵活性，选人工+自建词库；如果追求效率、内容量大自然语言处理需求强、预算充足，选第三方API

交付方式选单index.html还是app.py+templates？

交付方式决定验收标准适用哪一套(info_000005明确两种可选)，影响部署和用户体验

单index.html交付（mind_milestone）

为什么产出它：里程碑5部署环节的轻量实现方式

优点
  • 满足≤200KB硬性限制(info_000008)
  • 手机端即开即用，无需安装
  • 部署极简，copy即可
缺点
  • 无服务器端逻辑
  • 无法实现复杂后端功能
  • 无法做数据持久化

因果链：项目要求轻量手机端使用(info_000002)→单页面满足≤200KB(info_000008)→选index.html

关键信息：
  • 交付规格1：单个index.html样式脚本全内嵌(info_000005)
  • 验收条件：HTML+CSS+JS合计≤200KB(info_000008)

app.py+templates交付（mind_milestone）

为什么产出它：里程碑5部署环节的完整实现方式

优点
  • 功能完整，可实现所有验收条件
  • 支持数据库存储
  • 便于后续功能扩展
缺点
  • 需Python3环境运行
  • 需在8765端口部署
  • 不如单HTML便携

因果链：需要完整功能→Python服务器部署→功能完整但需环境→选app.py方案

关键信息：
  • 交付规格2：app.py+templates，python3 app.py在8765起(info_000005)
  • README.md需说明运行命令(info_000005)
怎么选：如果追求轻量、便携、满足≤200KB，选单index.html；如果需要完整功能、数据库存储、后续扩展，选app.py+templates
