# 为什么需要 doclearn？

## 背景

在需要从本地文档中快速检索信息时，我们有几个常见选择。但每个选择都有其局限性。

## 三个最接近的已有方案

### 1. ChatGPT API（OpenAI）

- **出处**: https://openai.com/api/
- **Archive备份**: https://web.archive.org/web/2024/https://openai.com/api/
- **做法**: 将文档内容发送给 ChatGPT API，利用大模型的语义理解能力回答问题
- **局限性**: 需要联网，API 调用有成本，存在数据隐私风险

### 2. LangChain 本地文档问答

- **出处**: https://python.langchain.com/docs/modules/data_connection/document_loaders/
- **Archive备份**: https://web.archive.org/web/2024/https://python.langchain.com/docs/modules/data_connection/document_loaders/
- **做法**: 使用 LangChain 框架加载本地文档，配合向量数据库和 LLM 进行问答
- **局限性**: 需要安装大量依赖，需要本地 LLM（如 GPT4All）或 API，需要配置向量模型

### 3. Obsidian 插件

- **出处**: https://obsidian.md/ 和 https://github.com/huminghere/obsidian-local-rest-api
- **Archive备份**: https://web.archive.org/web/2024/https://obsidian.md/
- **做法**: 使用 Obsidian 的 Local REST API 插件或 Text Generator 插件查询笔记
- **局限性**: 需要使用 Obsidian 作为笔记工具，插件能力受限，跨软件使用困难

## doclearn 与它们的差异

| 方案 | 联网依赖 | 依赖库 | 配置复杂度 | 适用场景 |
|------|---------|--------|-----------|---------|
| ChatGPT API | 必须联网 | API 调用 | 低 | 通用问答 |
| LangChain | 需要 LLM/API | 大量（>20个） | 高 | 开发者 |
| Obsidian 插件 | 可选 | Obsidian | 中 | Obsidian 用户 |
| **doclearn** | **零依赖** | **0-1个（可选）** | **零配置** | **任何人** |

## doclearn 的独特价值

1. **真正的离线运行**: 不需要任何网络连接，即使在内网隔离环境也能使用
2. **零外部依赖**: Python 标准库即可运行，pip install jieba 是可选增强
3. **可自定义评分规则**: 关键词权重、长度权重、位置权重全部可调
4. **即刻可用**: 解压即跑，无需配置 API key、下载模型或安装复杂依赖
5. **透明可审计**: 算法简单清晰，搜索结果可解释

## 何时选择 doclearn

- 文档数量 < 1000 篇
- 文档格式简单（txt/md）
- 需要快速部署、无运维负担
- 对数据隐私有严格要求
- 内网/离线环境

## 何时选择其他方案

- 需要深度语义理解 → ChatGPT API
- 需要处理 PDF/Word/HTML 等复杂格式 → LangChain
- 已经是 Obsidian 用户 → Obsidian 插件
