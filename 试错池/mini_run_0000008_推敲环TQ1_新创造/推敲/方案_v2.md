# 方案 v2

做一个纯本地文档问答工具，用关键词匹配+TF-IDF相似度返回最相关段落

运行：`python doclearn.py --path ./sample_docs --query "什么是Python"`

1. **原型程序** — doclearn.py：扫描文件夹读取txt/md文件，用关键词匹配+TF-IDF相似度返回最相关的段落；文件 doclearn.py, sample_docs/sample1.txt, sample_docs/sample2.txt；验收：python doclearn.py --path ./sample_docs --query "测试" 退出码为0且输出一段文本
2. **为什么新.md** — 对比ChatGPT API、LangChain本地文档问答、Obsidian插件三个方案，说明纯离线、零依赖、可自定义权重的差异；文件 为什么新.md；验收：文件包含三个方案名称且每个有http链接
3. **价值证明** — demo.py：对比本工具与直接grep搜索，统计查准率和耗时；文件 demo.py；验收：python demo.py 退出码0且打印至少两组数字
4. **给谁用.md** — 场景1-3：离线写作查笔记、开发者查代码、学生整理资料，每个场景写步骤；文件 给谁用.md；验收：文件存在且包含三个场景，每个场景至少3步

待核实假设：
- sample_docs文件夹实际存在且包含txt文件
- doclearn.py能正确解析txt/md文件内容
- ChatGPT API/LangChain/Obsidian的实际离线能力需核实
- TF-IDF相似度算法对短查询效果需验证

本版改动：
- 将原型从'txt/md/py/json四种格式'简化为'txt/md两种格式'，降低实现复杂度确保可验证
- 将'倒排索引'改为'关键词匹配+TF-IDF相似度'，更易实现且效果可验证
- 调整check要求从'有可观察的输出'明确为'输出一段文本'
- demo.py改为先运行原型生成结果，再用grep对比，先验证原型功能再对比
