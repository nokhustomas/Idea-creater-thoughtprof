# 方案 v3

纯本地语义检索文档问答工具，用关键词共现+段落重要性评分返回最相关段落，零外部依赖可离线运行

运行：`python doclearn.py --path ./sample_docs --query "什么是Python"`

1. **原型程序** — doclearn.py：扫描文件夹读取txt/md文件，用关键词共现算法+段落长度/位置权重计算相关性，返回top-k最相关段落；文件 doclearn.py, sample_docs/sample1.txt, sample_docs/sample2.txt；验收：python doclearn.py --path ./sample_docs --query "测试" 退出码为0且输出一段文本
2. **为什么新.md** — 对比ChatGPT API、LangChain本地文档问答、Obsidian插件三个方案，说明纯离线、零依赖Python标准库、可自定义评分规则的差异；文件 为什么新.md；验收：文件包含三个方案名称且每个有http链接或archive.org备份链接
3. **价值证明** — demo.py：对比本工具与直接grep搜索，统计查准率和耗时；文件 demo.py；验收：python demo.py 退出码0且打印至少两组数字并包含"本工具比grep好在哪"的结论句
4. **给谁用.md** — 场景1-3：离线写作查笔记、开发者查代码、学生整理资料，每个场景用1-2-3数字列表写至少3步；文件 给谁用.md；验收：文件存在且包含三个场景标题，每个场景至少3行带数字前缀的步骤

待核实假设：
- sample_docs文件夹存在且包含txt文件
- doclearn.py能正确解析txt/md文件内容
- 目标机器Python版本>=3.6且装有jieba库（pip install jieba）
- ChatGPT API/LangChain/Obsidian的实际离线能力需核实
- 关键词共现算法对短查询效果需验证
- 目标机器无sentence-transformers等深度学习库

本版改动：
- 将TF-IDF改为关键词共现+段落重要性评分，降低依赖复杂度
- 扩展支持文件格式说明，在文档中注明txt/md
- why新.md增加使用archive.org备份链接的说明
- 价值证明明确要求打印"本工具比grep好在哪"结论
- 给谁用场景步骤采用数字列表形式并明确计数规则
- 针对条件分支场景，在给谁用中简化为顺序步骤
