# 餐饮小红书代运营 SOP 手册

> 任务点名要求交付：sop.md（标准操作流程手册）  
> 用途：把 30 天 0 成本拿到第一个付费用户的全流程沉淀为可复制的 SOP，下一次直接套用

**版本**：v1.0  
**编写日期**：Day 30 复盘后  
**适用场景**：0 成本（仅 1 台 Mac + AI 订阅）启动餐饮小红书内容陪跑业务

---

## 〇、SOP 总览（30 天里程碑）

| 阶段 | 天数 | 核心产出 | 关键指标 |
|---|---|---|---|
| 调研 | Day 1-2 | 20+ 家调研报告 | 城市分层 + 预算归纳 |
| 定价 | Day 3-5 | 20+ 家竞品定价表 | 全托/半托分价位 |
| 案例 | Day 6-8 | 2 个免费陪跑案例 | 500+ 阅读 + 授权书 |
| 引流 | Day 9-12 | 闲鱼/小红书/备用 | 1 商品 + 1 笔记 + 1 备用 |
| 私域 | Day 13-20 | 群 + 朋友圈 + 话术 | 5+ 人入群 + 每周 3 次 |
| 转化 | Day 21-28 | 报价单 + 合同 + 筛选 | 1 付费签约 |
| 复盘 | Day 29-30 | 复盘 + SOP | 14 天验证假设 |

## 一、Day 1-2 调研 SOP

### 目标
20+ 家快餐店样本，按城市等级分层，归纳预算意愿 + 决策周期

### 操作步骤
1. 大众点评按城市等级搜索目标关键词
   - 关键词：快餐店引流、小吃店不会做自媒体、夫妻店想做线上、外卖运营痛点
   - 城市：北京/上海/广州/深圳（一线）、成都/杭州/重庆/西安（新一线）、其他省会（二三线）
2. 收集店家痛点和联系方式（电话/微信/大众点评 ID）
3. 小红书搜索同类笔记，记录餐饮老板的困惑和付费意愿
4. 微信/社群直接询问餐饮老板的运营困境和预算
5. 汇总到 调研数据.csv（≥20 行）
6. 撰写 用户调研报告.md（含数据来源链接）

### 关键模板
- 调研数据.csv 字段：编号、城市等级、品类、店名、痛点、月销、是否做过自媒体、预算意愿、决策周期、联系方式、数据来源
- 用户调研报告.md 包含：分类（北上广深/新一线/二三线）、预算意愿归纳（非预设）、决策周期归纳

### 验收
```bash
grep -qE '(一线|新一线|二线|三线)' 用户调研报告.md && \
grep -q '20' 用户调研报告.md && \
wc -l 调研数据.csv | awk '{exit !($1>20)}'
```

## 二、Day 3-5 竞品定价 SOP

### 目标
20+ 家竞品定价（闲鱼/淘宝/抖音/美团），区分全托/半托

### 操作步骤
1. 闲鱼搜索「餐饮代运营」，筛有销量+评价的商家（警惕刷单）
2. 淘宝搜索同类服务，记录价格区间
3. 抖音搜索「餐饮代运营」，看商家主页报价
4. 美团找代运营服务商，记录报价
5. 区分全托（打包服务）和半托（仅内容生产）两类
6. 各收集 10+ 家
7. 计算每类价格区间 + 中位数
8. 标注每条数据的来源链接
9. 撰写 竞品定价表.md

### 关键模板
- 竞品数据.csv 字段：编号、平台、商家名、服务类型（全托/半托）、价格、销量、评价数、来源链接、是否刷单嫌疑
- 竞品定价表.md 包含：全托/半托分价位、来源链接、是否可信

### 验收
```bash
grep -q '全托\|半托' 竞品定价表.md && \
wc -l 竞品数据.csv | awk '{exit !($1>20)}' && \
grep -qE '(闲鱼|淘宝|抖音|美团)' 竞品定价表.md
```

## 三、Day 6-8 案例打造 SOP

### 目标
2 个免费陪跑案例（500+ 阅读 + 书面授权）

### 操作步骤
1. 写 店家筛选标准.md：大众点评 ≥3.5、月销 ≥500、自然流量意愿
2. 通过小红书「餐饮老板交流群」、本地餐饮社群物色候选人
3. 大众点评核实评分和月销
4. 电话/微信沟通确认意愿
5. 签 书面同意书.md（必须签，案例才能展示）
6. 用 AI（ChatGPT/Claude）生成账号定位 + 内容规划
7. AI 输出不达标 → 人工代写补充
8. 整理 案例1_xxx.md / 案例2_xxx.md（含阅读量、互动数据）
9. 跟进发布，记录实际阅读量

### 关键模板
- 店家筛选标准.md：包含评分阈值（3.5+）、月销阈值（500+）、书面同意要求
- 书面同意书.md：含店家签字、授权范围、撤回条款
- 案例文档：含店家简介、定位、内容规划、30 天数据、阅读量截图

### 验收
```bash
ls 案例*.md | wc -l | awk '{exit !($1>=2)}' && \
ls 书面同意书.md 店家筛选标准.md && \
grep -q '阅读量' 案例*.md && \
grep -qE '3\.[5-9]|4\.' 店家筛选标准.md && \
grep -qE '[5-9][0-9]{2,}' 案例*.md
```

## 四、Day 9-12 引流 SOP

### 目标
1 闲鱼商品 + 1 小红书笔记 + 1 备用方案，覆盖餐饮老板高频场景

### 操作步骤
1. 写 闲鱼商品文案.md（标题含「餐饮代运营」「餐饮引流」）
   - 类目：生活服务-营销推广
   - 价格：998 元体验价
   - 配图：2 个案例数据截图
2. 写 小红书笔记.md（标题如「帮 2 家餐饮店从 0 到 1 做自媒体」）
   - 嵌入真实案例数据
   - 评论区引导加微信
3. 同步发布闲鱼 + 小红书
4. 写 备用引流方案.md
   - 大众点评商家号（需核实是否要营业执照）
   - 知乎/微博引流（说明从这些平台到微信的路径）
5. 记录各平台发布后的曝光/浏览数据

### 关键模板
- 闲鱼商品文案.md：标题、详情、配图建议、价格
- 小红书笔记.md：标题、正文、标签、配图建议
- 备用引流方案.md：各平台从浏览 → 加微信的完整路径

### 验收
```bash
ls 闲鱼商品文案.md 小红书笔记.md 备用引流方案.md && \
grep -q '微信' 备用引流方案.md && \
grep -qE '代运营|引流|获客' 闲鱼商品文案.md 小红书笔记.md
```

### 风险预案
- 闲鱼商品被删：换「餐饮内容策划」「餐饮新媒体」等替代词
- 小红书限流：换号重发 / 改用备用方案
- 大众点评商家号需营业执照：放弃，改为知乎/微博

## 五、Day 13-20 私域 SOP

### 目标
首批 ≥5 人入群 + 每周 3 次群分享

### 操作步骤
1. 整理 day9-12 通过闲鱼/小红书/备用渠道添加的微信用户名单
2. 逐一发送欢迎话术（见 私域话术.md 模板 A/B/C）
3. 创建微信群「餐饮老板自媒体交流圈」
4. 设置群公告 + 群规
5. 待首批 ≥5 人后正式运营
6. 按 朋友圈发布计划.md 每日发 1-2 条
7. 按 群运营sop.md 每周三/五/日 20:00 群分享
8. 每日统计进群人数和发言人数

### 关键模板
- 私域话术.md：欢迎话术 / 跟进话术 / 转化话术
- 朋友圈发布计划.md：每日内容栏目 + 28 天完整计划
- 群运营sop.md：建群 / 周分享 / 死群激活

### 验收
```bash
ls 私域话术.md 朋友圈发布计划.md 群运营sop.md && \
grep -q '3次' 群运营sop.md && \
grep -qE '欢迎话术|跟进话术|转化话术' 私域话术.md
```

### 风险预案
- 群内用户不发言：发红包/提问式内容激活
- 话术被微信判定营销：减少频繁群发、换正常聊天语气
- 首批不足 5 人：延迟建群，继续从引流渠道加微信

## 六、Day 21-28 转化 SOP

### 目标
1 付费签约（998 元或 1500 元）

### 操作步骤
1. 从私域数据中导出 day13-20 期间所有用户的互动记录
2. 按 高意向用户筛选标准.md 标记 S/A/B/C 级
3. 人工逐个判断，剔除非目标客户
4. day21-22 优先私信 S 级（话术见 私域话术.md 模板 A）
5. 对方回复后发送 报价单.md
6. 对方确认后发送 服务合同.md，收到签字/付款
7. 对方有疑虑 → 提及 15 天 20% 退款政策（见 报价单.md / 服务合同.md）
8. 每日统计发出报价数、已签约数、已退款数
9. 客户申请退款时填 退款申请表.md，3 个工作日内审核

### 关键模板
- 报价单.md：首月 998 / 常规 1500 / 季度 3980
- 服务合同.md：含 20% 退款条款
- 高意向用户筛选标准.md：7 天互动 ≥3 次
- 退款申请表.md：3 个必填字段

### 验收
```bash
ls 报价单.md 服务合同.md 高意向用户筛选标准.md 退款申请表.md && \
grep -qE '20%' 报价单.md 服务合同.md && \
grep -q '7天' 高意向用户筛选标准.md
```

### 风险预案
- 误判高意向：复核筛选条件、增加「必须有具体问题」门槛
- 报价过高流失：准备 599 元单周体验套餐
- 退款纠纷：合同明确退款条件

## 七、Day 29-30 复盘 SOP

### 目标
数据记录 + 复盘报告 + 14 天验证假设

### 操作步骤
1. 整理 数据记录表.md（每日数据汇总）
   - 曝光 / 咨询 / 入群 / 报价 / 转化
2. 若成功签约 → 写 复盘报告.md（含 SOP 提炼）
3. 若未成功 → 写 3 条可验证改进假设（验证周期 14 天）
   - 假设 1：引流渠道扩充（入群 +50%）
   - 假设 2：群运营增加诊断（咨询 +20%）
   - 假设 3：增加 599 元套餐（签约 +20%）
4. 验证指标：咨询转化率提升 ≥20% 或 入群人数提升 ≥50%

### 关键模板
- 数据记录表.md：每日指标 + 累计 + 周报
- 复盘报告.md：成功/失败两条路径

### 验收
```bash
ls 复盘报告.md sop手册.md 数据记录表.md && \
grep -qE '14天|20%|50%' 复盘报告.md
```

## 十、复用本 SOP 的步骤

1. **复制本目录所有 .md / .csv 文件**
2. **修改 案例*.md 中的店名/数据**（不能复用）
3. **修改 调研数据.csv 中的店名/数据**（不能复用）
4. **重新走 30 天流程**
5. **每次复盘后更新本 SOP 手册**

## 十一、前提假设（README 同步）

- 假设快餐类小微企业主确实愿意为代运营付费（需进一步验证）
- 假设免费案例店家愿意书面同意展示（需电话确认）
- 假设小红书/闲鱼发帖不被删（若被删用备用方案）
- 假设 AI 生成的账号定位和内容规划质量能满足店家实际需求（若不达标用人工代写补充）
- 假设大众点评商家号 0 成本可完成注册（需核实是否需要营业执照）
