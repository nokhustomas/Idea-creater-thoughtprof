# 竞品分析维度与标准（Competitor Analysis Criteria）

> 与 `competitor_analysis_plan.md` 配套使用。本文件给出：维度定义、评分刻度、权重、汇总表模板。

---

## 1. 维度定义（10 项）

| # | 维度 | 定义 | 1 分（差） | 5 分（强） |
|---|------|------|-----------|-----------|
| 1 | 入门门槛 | 注册、登录、学习提示词的难度 | 要写代码/付费才能用 | 一句话就能开 |
| 2 | 端到端时延 | 从一句话到可下载成品的耗时 | >30 分钟 | <60 秒 |
| 3 | 成品可下载 | 是否给真实可下载文件 | 只在网页看 | zip/PDF/源码 |
| 4 | 成品可改 | 拿到后能不能继续修改 | 黑盒 | 源码 / 可编辑 |
| 5 | 定价透明度 | 价格是否清晰 | 完全不透明 | 三档明示 |
| 6 | 免费档 | 是否有可用的免费档 | 无 | 有且足够用 |
| 7 | 中文支持 | 中文 prompt 的接受度与排版 | 不支持中文 | 中文排版漂亮 |
| 8 | 过程透明 | 用户能否看到机器在做什么 | 黑盒 | 实时日志 |
| 9 | 可审计性 | 是否有归档、日志、版本 | 无 | 全链路落档 |
| 10 | 团队协作 | 多人能不能一起用 | 单机 | 多人 + 权限 |

## 2. 评分刻度（每维度统一）

- 1 = 完全不行 / 不支持
- 2 = 差 / 勉强能用
- 3 = 一般 / 能用但有缺陷
- 4 = 好 / 大多数场景够用
- 5 = 强 / 行业领先

## 3. 权重（与本系统目标对齐）

| 维度 | 权重 | 理由 |
|------|------|------|
| 入门门槛 | 0.15 | 这是「一句话开局」的命门 |
| 端到端时延 | 0.15 | 时延是体验核心 |
| 成品可下载 | 0.10 | 客户要拿走 |
| 成品可改 | 0.10 | 客户要再改 |
| 定价透明度 | 0.05 | 影响信任 |
| 免费档 | 0.05 | 影响试用 |
| 中文支持 | 0.10 | 国内主战场 |
| 过程透明 | **0.15** | Idea-Pusher 的差异化卖点 |
| 可审计性 | **0.10** | 企业档卖点 |
| 团队协作 | 0.05 | 暂作次级 |

加权得分 = Σ (分数 × 权重)，满分 5.00。

## 4. 数据采集模板（每竞品一行）

```
竞品名 | 类型 | 官网 | 试用日期 | 维度1 | 维度2 | ... | 维度10 | 加权分 | 备注
```

示例：

```
ChatGPT Plus | 对话 AI | https://chat.openai.com | 2025-xx-xx | 4 | 3 | 2 | 3 | 4 | 4 | 4 | 2 | 2 | 3 | 3.10 | 强通用、弱归档
```

| Vercel v0 | - | 前端快 | 不出脚本 |

| ... | ... | ... | ... |

## 6. 结论判定规则

- 加权分 ≥ 4.0：竞品威胁大，必须正面回应（功能追平或差异化切割）。
- 3.0 ≤ 分 < 4.0：常规对手，在文案里点对点避其锋。
- < 3.0：可忽略。

## 7. 与本系统的回填动作

1. 若「过程透明」普遍 < 3：本系统强调「实时日志」卖点。
2. 若「入门门槛」普遍 ≥ 4：本系统强调「无需写提示词」。
3. 若「中文支持」普遍 < 3：本系统强调「中文排版与本土案例」。
4. 若「可审计性」普遍 < 3：本系统强调「全程留档 + 总账」。

## 8. 评审与回归

- 每 6 个月重测一次。
- 同一竞品由 ≥ 2 人独立打分，分歧 > 1.5 分时引入第三人裁决。
- 维度或权重变更需在文件末「修订记录」登记。
