# 用户调研方案（User Research Plan）

> 归属：想法推进器（Idea-Pusher）客户用网页系统
> 目的：弄清目标用户群的真实需求、使用习惯与偏好，作为后续原型设计与迭代的依据。

## 1. 调研目标

1. 量化：**谁会用这套「一句话开局 → 自动出成品」的系统**（年龄、职业、技术水平）。
2. 定性：**他们最在意的痛点是什么**——是速度、价格、可控性，还是成品质量。
3. 验证：客户对当前三档定价（免费/¥29/¥199）的接受度与心理锚点。
4. 沉淀：把调研结论反馈到 `competitor_analysis_criteria.md` 的权重里。

## 2. 目标用户群（前置假设，待核实）

| 群组 | 描述 | 占比假设 | 关键诉求 |
|------|------|----------|----------|
| 个人创作者 | 写公众号 / 做小工具 / 写读后感 | ~40% | 快速、能跑、不用学 |
| 小微团队 | 2–10 人工作室，需要脚本 / 报告 | ~25% | 性价比、可改、可归档 |
| 教师与科普者 | 写课件、做演示页 | ~15% | 排版、导出、可视化 |
| 企业内部 | 文档 / 审核 / 培训资料 | ~15% | 审计、可追溯、批量 |
| 其他 | 不明 | ~5% | 探索 |

> 占比待核实。调研结束后替换为真实数字。

## 3. 调研方法

### 3.1 问卷（定量）
- 渠道：系统首页底部链接 + 微信群 + 邮件列表。
- 长度：≤ 12 题，5 分钟内完成。
- 投放：至少 100 份有效回收（待核实）。
- 文件：`user_research_questions.md`。

### 3.2 访谈（定性）
- 形式：30 分钟一对一视频 / 语音。
- 样本：8–12 人（待核实），覆盖上面 4 个群组各 2–3 人。
- 文件：`user_research_questions.md` 的访谈提纲部分。
- 录音 → 文字转写 → 标签归类。

### 3.3 行为数据（被动）
- 借助系统自身的 `TJ_ROOT/logs/usage.json` 与 `ledger.txt`：
  - 提交时段分布
  - 档位选择分布
  - 重新提交率（说明一次没满意）
  - 完成时长分布

## 4. 实施步骤

| 阶段 | 时长 | 产出 |
|------|------|------|
| 准备问卷 + 访谈提纲 | T+0 | 本文件 + questions.md |
| 小范围预调研（n=5） | T+3 | 修订问卷 |
| 大范围投放 | T+7 | ≥100 份问卷 |
| 访谈 | T+14 | 8–12 份转写 |
| 数据清洗 + 标签 | T+18 | 标签表 |
| 报告 | T+21 | 本文件末尾追加「调研结论」段 |

## 5. 调研维度

- **基本信息**：年龄区间、职业、技术自评（1–5）。
- **使用习惯**：当前用什么工具完成类似任务 / 每周频次。
- **需求**：最想自动化的三个动作。
- **偏好**：成品形式（网页/脚本/文档/PDF）、交付方式（zip/邮件/链接）。
- **价格**：能接受的单次价位、对免费档的态度。
- **痛点**：当前最大的挫败感来自哪里。

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| 回收样本偏差 | 同时挂行为数据补盲 |
| 题目引导偏差 | 题目随机排序 + 反向题 |
| 访谈对象不配合 | 准备小礼品（电子卡片） |
| 结论被主观偏好带偏 | 双人独立编码，Kappa 校验 |
