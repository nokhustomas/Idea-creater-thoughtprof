# 用户测试计划（User Test Plan）

> 归属：想法推进器（Idea-Pusher）客户用网页系统
> 目的：在真实用户跑通端到端流程之前，把可用性问题提前暴露。

## 1. 测试目标

1. 验证「一句话 → 推敲 → 验收 → 出成品 → 下载」流程顺畅。
2. 验证三档定价的呈现与档位切换体验。
3. 暴露首页文案 / 按钮 / 错误提示的可读性问题。
4. 收集反馈进入 `user_feedback_form.md`，落到 `iteration_log.md`。

## 2. 参与人数与方式（前置假设，待核实）

- 参与人数：8–12 人（待核实）。
- 邀请方式：从问卷回收者中筛选 + 工作室同事外加 2 名「完全没用过」的小白。
- 测试方式：远程视频 + 屏幕共享（30 分钟/场）。
- 设备：PC + 手机各半。
- 录音 + 录屏，取得同意。

## 3. 测试任务清单（每场必跑）

| # | 任务 | 通过标准 |
|---|------|----------|
| T1 | 打开首页，能在 5 秒内看清在卖什么 | 用户复述出「一句话开局、自动出成品」 |
| T2 | 输入一句话（自选话题）并选档提交 | 提交后看到进度区出现日志 |
| T3 | 等待并刷新拿到成品下载链接 | 看到 zip / reader.html 链接 |
| T4 | 下载并打开 zip | 文件可解压且至少含 1 个真文件 |
| T5 | 重新提交一次并尝试切档 | 价格数字能跟着档位变 |
| T6 | 故意提交空话题 | 看到明确错误提示，不崩 |
| T7 | 故意输入 1000+ 字 | 不崩，提示长度限制 |

## 4. 主持流程（30 分钟）

| 时间 | 内容 |
|------|------|
| 0–3 | 寒暄、录音授权、保密说明 |
| 3–5 | 介绍产品（不剧透功能列表） |
| 5–20 | 用户自由跑 T1–T7，主持只观察不引导 |
| 20–28 | 半结构化提问：哪里卡？哪里想多点？ |
| 28–30 | 致谢，发小礼品卡 |

## 5. 度量指标

- 完成率：跑通 T1–T4 的人数 / 总人数（目标 ≥ 80%）。
- 一次成功率：T3 第一次就拿到成品的人数 / 总人数。
- 平均时长：T1 → T3 用时。
- 卡点表：每场记录 1–3 个最大卡点。
- NPS：每场收一个 0–10 推荐分。

## 6. 反馈收集

- 现场反馈用 `user_feedback_form.md` 一页纸记录。
- 会后当天上传原始录像 + 转写到测试档案。
- 量化指标当天汇总到 `iteration_log.md`。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 网络断 | 提供本地备用 `app.py` 启动方式 |
| 用户不开口 | 准备暖场问题 |
| 录音失败 | 双手机录备份 |
| 隐私顾虑 | 保密承诺 + 删除选项 |
