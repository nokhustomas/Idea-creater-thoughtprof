# 想法推进器 V2 客户端网页系统

> 让客户从浏览器走完「一句话想法 → 接单 → 推敲 → 制作 → 自检 → 拿成品」的全流程。
> 本版本（V2）直接接真机器，读真队列、真档案、真总账。

---

## 1. 启动

```bash
# 正常启动（默认 8080 端口）
python3 app.py

# 指定端口
python3 app.py --port 9000

# 真模式自检：仅验证能读到 TJ_ROOT 下三个真文件，验证完退出 0
python3 app.py --check

# 演示模式：题面池目录不存在时自动创建，允许自检脚本造演示数据
TJ_DEMO=1 python3 app.py

# 自检脚本（演示模式 60 秒内退出 0）
TJ_DEMO=1 python3 selfcheck.py
```

环境变量 `TJ_ROOT` 决定根目录，默认 `/opt/tuijinqi`。

## 2. 流程设计

客户在浏览器里走 5 步：

| 步骤 | 页面 | 动作 | 后台落点 |
| --- | --- | --- | --- |
| 1 | `/` 首页 | 选档位 + 写原话 + 提交 | 题面文件落到 `$TJ_ROOT/题面池/客户_<单号>.txt`；`logs/队列.txt` 追加一行 |
| 2 | 后台守护 | 守护进程从队列取单，次数写 0，开盘 | `runs/run_XXXXXXX/` 建档 |
| 3 | `/progress` 进度页 | 实时读 `验收.txt` / `llm_usage.jsonl` 推断状态 | 不写盘，只读 |
| 4 | 后台 | 自检不达标则自动重跑，直到达标或到本档轮数上限 | 同一 `run_XXXXXXX/` 内更新 |
| 5 | `/download` 成品页 | 列出 `out/` 下的 `*_成品.zip`、`成果导读.html` 提供下载 | 只允许 `out/` 内的路径，防止越权 |

状态推断规则（严格按客户原话）：

- **排队中**：还没出现 `验收.txt`
- **在跑·已调用 N 次**：有 `llm_usage.jsonl`、无达标结论，N 为该 run 内的合法 JSON 行数
- **达标**：`验收.txt` 末行以 `结果 达标` 开头
- **未达标·重跑中**：`验收.txt` 末行以 `结果 未达标` 开头，且仍在档位轮数内

## 3. 定价策略

延续 V1 的三档定价，理由如下：

| 档位 | 价格 | 轮数 | 理由 |
| --- | --- | --- | --- |
| **基础档** | **免费（¥0）** | **2** 轮 | **获客漏斗**。让客户零成本尝鲜，跑得通才有人愿意付钱。一个没试过的客户不会直接掏 ¥199。免费不是不赚钱，是把获客成本前置到模型调用费上，赌的是复购和口碑。 |
| **进阶档** | **¥29** | **4** 轮 | **低价锚点 / 主力档**。把 ¥29 摆在 ¥199 旁边，进阶档就显得"很便宜"，是企业版低价锚点的经典玩法（来自 V1 原话）。绝大多数愿意付费的客户最终会落在这档，¥29 走量、单量、续费，是现金牛。 |
| **企业档** | **¥199** | **8** 轮 | **高端 / 高客单**。承接对结果稳定性要求高、有合规 / 演示需求的客户。8 轮自愈意味着真正复杂的题目也能收敛到"达标"。定价 ¥199 是把单次服务拉到一个"决策成本"的位置，让客户为"稳"付溢价。 |

合计三档：0 / 29 / 199，覆盖从免费尝鲜到高客单的全段。

**为什么不只设一档？** 一档要么太贵（吓跑所有人）要么太便宜（覆盖不了深度服务的成本）。三档让客户自己按需挑，比强制定价的接受度高得多。

**为什么 29 和 199 间隔这么大？** 中间隔了 ¥29 → ¥199 两个量级，逼着"犹豫型"客户做决策：要么选 ¥29 走量，要么直接上 ¥199 求稳。没有中间档是为了避免客户长期停在中间选项。

## 4. 题面池目录规则

- **路径**：`$TJ_ROOT/题面池/` （**注意是中文目录名"题面池"，和客户原话一致**）
- **不存在时**：自动创建，不报错。这是 V2 的硬要求，让新部署的机器也能直接起服务。
- **命名**：`客户_<单号>.txt`，单号自增（从 `logs/队列.txt` 中已出现的最大 `客户<N>` + 1）
- **提交**：写题面文件后，向 `$TJ_ROOT/logs/队列.txt` 追加一行 `题面绝对路径|客户<单号>|客户|0`

为什么要自动创建？因为客户原话明说"没有这些目录时自动建，并允许 TJ_DEMO=1 造几条演示单方便测试"。题面池目录没有，客户原话就无处落盘，整条链路就断了。把它做成幂等 `os.makedirs(..., exist_ok=True)` 是最稳的做法。

## 5. 口令

- 默认口令：`admin123`（部署时通过环境变量或改源码可换）
- 校验：每次 GET / POST 请求前检查 `Authorization` header
- 失败：返回 `401 Unauthorized`

这是 V1 留下的最小权限边界。客户端网页是公开访问的，但提交单和下载成品这两个动作必须验证，避免被脚本灌垃圾单。

---

## 6. 路径安全

下载接口做两道校验：

1. `os.path.realpath` 后必须仍在 `$TJ_ROOT/runs/<run>/out/` 内（防 `..` 越权）
2. 路径里必须含字面 `out/`（防直接读到 runs 根的敏感文件）

两道都过了才允许 `sendfile`，否则 404。

## 8. 前提假设

- **题面池目录命名为「题面池」**符合客户原话中的约定（`$TJ_ROOT/题面池/客户_<单号>.txt`），与代码里 `os.path.join(tj_root, "题面池", filename)` 一致。
- **口令默认设为 `admin123`**，实际部署时可修改。
- **`TJ_ROOT` 默认 `/opt/tuijinqi`**，与客户原话一致；可由环境变量覆盖。
- **演示模式 `TJ_DEMO=1`** 仅用于自检造数据，不影响真模式的真实读写。
